# Travely frontend

Цей репозиторій містить лише React/TypeScript фронтенд. Django API, міграції, JWT і завантаження фото живуть у [окремому бекенд-репозиторії](https://github.com/alka-Ukraine/python).

## Локальний запуск двох репозиторіїв

1. У бекенд-репозиторії скопіюйте `.env.sample` у `.env`, задайте власний `DJANGO_SECRET_KEY` і запустіть `make up`. API та Swagger будуть на `http://localhost:8000/api/` і `http://localhost:8000/swagger/`.
2. У цьому репозиторії перейдіть у `frontend/`, виконайте `npm ci` та `npm run dev`. Відкрийте адресу, яку покаже Vite (зазвичай `http://localhost:5173/`).

Під час локальної розробки Vite проксирує **всі** `/api` та `/media` запити до `http://127.0.0.1:8000`. Якщо бекенд слухає іншу адресу, задайте `API_PROXY_TARGET` у `frontend/.env` (зразок — `frontend/.env.example`). Пошук локацій, JWT, пости та фото використовують один і той самий API.

Фронтенд можна окремо запустити через Docker: скопіюйте кореневий `.env.example` у `.env` та виконайте `make up`. Docker Compose цього репозиторію запускає тільки фронтенд і звертається до бекенду через `host.docker.internal:8000`; бекенд має бути запущений окремо.

## Production

`cd frontend && npm run build` створює статичну збірку в `frontend/dist`. На статичному хостингу Vite-проксі не працює: перед збіркою задайте `VITE_API_BASE_URL=https://ваш-бекенд/api` і дозвольте домен фронтенду в `CORS_URL` бекенду. Для завантажених фото бекенду потрібне постійне медіасховище.

Без оновленого бекенду маршрути `/api/city-posts/`, `/api/city-covers/` і `/api/token/` недоступні: сторінка показує помилку, а збереження матеріалів не відбувається.
